# 财报排雷与估值方法论

红旗判定逻辑逐条对应 `scripts/ratios.py` 中的 `check_red_flags` 函数。数据
缺失一律不判红旗、不推测填充，`detail` 写「未获取到」——这是贯穿整个模块
的硬规则，任何一条红旗只要输入缺失，直接落入「未获取到」分支，不会去猜一
个「大概率清白」的结论。

## 十条红旗

| 代码 | 名称 | 判定阈值 | 含义 | 一票否决 |
|---|---|---|---|---|
| CASH_PROFIT | 净现比 | 净现比（经营现金流/净利润）< 0.7 命中；若最近两个年度的净现比历史均 < 0.5，额外触发否决 | 利润有没有真实现金流支撑，比值过低说明利润质量差，可能是应收堆积或提前确认收入 | 仅「连续两年低于 0.5」时触发 |
| ACCRUAL | 总应计比率 | `(净利润 - 经营现金流) / 总资产` > 0.10 命中 | 应计项目占资产比例过高，是财务操纵的经典信号之一 | 否 |
| RECEIVABLE | 应收增速超营收 | 应收账款同比增速 - 营业收入同比增速 > 20（百分点）命中 | 应收增长明显快于收入增长，可能是放宽信用政策冲业绩或收入注水 | 否 |
| GOODWILL | 商誉占净资产 | 商誉 / 净资产 > 0.30 命中 | 商誉占比过高，未来存在大额减值风险 | 否 |
| RECURRING | 扣非占归母 | 扣非净利润 / 归母净利润 < 0.70 命中 | 主营业务盈利能力弱，利润靠非经常性损益支撑 | 否 |
| BIG_DEPOSIT_LOAN | 大存大贷 | 货币资金/总资产 > 0.30 **且** 有息负债/总资产 > 0.30 同时成立命中 | 账上现金很多同时借款很多，是財务造假或资金被占用的常见特征 | 是（命中即触发） |
| AUDIT_OPINION | 审计意见 | 审计意见文本中不包含「无保留」命中（即非标准无保留意见，含带强调事项段、保留意见、否定意见、无法表示意见） | 审计师对财报本身有保留，是最高等级的警示信号之一 | 是（命中即触发） |
| PLEDGE | 股权质押 | 控股股东质押比例 > 50% 命中 | 大股东质押比例过高，存在爆仓、控制权变更风险 | 是（命中即触发） |
| DELISTING_RISK | 退市风险 | 布尔字段为真命中（如被 ST/*ST/交易所退市风险警示） | 公司存在退市可能性，权益可能大幅缩水甚至归零 | 是（命中即触发） |
| INVESTIGATION | 立案调查 | 布尔字段为真命中（证监会或交易所立案调查） | 公司或高管正被立案调查，存在重大不确定性 | 是（命中即触发） |

看板中红旗展示规则：命中标 ❗，未命中标 ✓，缺失（未获取到）需单独标注，不
与「未命中（✓）」混淆——见下方「未获取到 ≠ 已核查且清白」。

## 一票否决红旗小结

六条否决触发路径中，五条来自无条件即触发否决的标记：`BIG_DEPOSIT_LOAN`、
`AUDIT_OPINION`、`PLEDGE`、`DELISTING_RISK`、`INVESTIGATION`——这五项命中
即一票否决，与其他条件无关；第六条来自 `CASH_PROFIT`，它平时不具备 veto
能力，只有在满足「连续两年低于 0.5」这一特殊条件时才额外触发否决。合计六
条否决触发路径，对应 scoring.md 中列出的六条。

## 未获取到 ≠ 已核查且清白（关键限制）

当前流水线中，以下五条红旗在 A 股、港股、美股任何市场都没有接入数据源，
永远返回 `hit=False`、`detail="未获取到"`：

- RECURRING（扣非占归母）——A 股新浪源与港股/美股 yfinance 都没有扣非净
  利润科目
- AUDIT_OPINION（审计意见）——流水线未对接审计意见数据源
- PLEDGE（股权质押）——流水线未对接股权质押数据源
- DELISTING_RISK（退市风险）——流水线未对接退市风险预警数据源
- INVESTIGATION（立案调查）——流水线未对接立案调查公告数据源

这五条里有四条（AUDIT_OPINION、PLEDGE、DELISTING_RISK、INVESTIGATION）
同时具备一票否决权，这意味着**一票否决机制目前大部分时间处于休眠状态**：
不是这些公司真的没有问题，而是当前流水线看不到。这是本方法论最重要的一条
限制，必须在看板中用醒目方式提示，不能让「回避」或「没有触发否决」被误读
成「财务干净」的判断。

在实测的两个样本中：600519（贵州茅台，A 股）在真实数据下 10 条红旗里只有
3 条能拿到真实数据评估（另外 7 条读到「未获取到」）；AAPL（美股）在真实数
据下有 4 条能拿到真实数据评估。看板中出现「回避」或红旗大面积「未获取到」
时，必须明确写清楚这是「数据拿不到、无法判断」，还是「数据拿到了、确实
命中红旗」，两者是完全不同性质的结论，不允许混为一谈。

## 杜邦三因子分解的读法

`ratios.dupont(net_profit, revenue, total_assets, equity)` 返回：

- `net_margin`（净利率）= 净利润 / 营业收入 —— 反映每一元收入能留下多少利润
- `asset_turnover`（总资产周转率）= 营业收入 / 总资产 —— 反映资产使用效率，
  越高说明单位资产创造的收入越多
- `equity_multiplier`（权益乘数）= 总资产 / 股东权益 —— 反映杠杆水平，越高
  说明财务杠杆越高
- `roe`（净资产收益率）= 三者相乘，任一分量缺失则 `roe` 为 `None`

解读要点：ROE 相同的两家公司，拆解后可能一家靠高利润率、一家靠高周转、一家
靠高杠杆撑起来，后者的可持续性和风险都不同——杠杆撑起来的高 ROE 在下行周
期更脆弱。任一分量为 `None` 时不得用假设值补全，直接说明「杜邦分解数据不
全，无法拆解」。

## 估值分位口径

口径：PE 五年分位——把当前 PE(TTM) 放到过去五年（约 1220 个交易日）PE 序列
中排序，得到分位数。25 分位对应的历史价格作为估值锚下沿，75 分位对应的历史
价格作为估值锚上沿。

**换算方式（不需要单独取 EPS）**：分位价 = 现价 ×（分位 PE / 当前 PE）。因为
PE = 价格 / 每股收益，同一时间窗口内盈利视为不变，所以「分位 PE 相对当前 PE
的比例」等于「分位价相对现价的比例」，直接用现价乘以 PE 比例换算，不必单独
取 EPS 再重算一遍。这一步在 `scripts/compute.py` 的
`derive_valuation_anchor(pe_block, current_price, market)` 中实现：从
`sources_cn.fetch_pe_history` 取回的 PE(TTM) 历史序列中筛掉非正值（PE 为负
或零的交易日不参与分位数计算），计算 25/75 分位 PE，再按上述公式换算成价
格，最终调用 `scripts/pricing.py` 的 `valuation_anchor(pe_percentile_25_price,
pe_percentile_75_price)` 取 min/max 构造区间；该函数本身仍然不关心这两个价
格是怎么算出来的，只负责取 min/max。

**数据来源与限流**：PE 历史只对 A 股实现，来自 `akshare.stock_value_em`，
该调用直接向东财发起 HTTP 请求、绕开 `http_client.HttpClient` 的限流器，不
计入东财 2 秒间隔与 10 次调用上限，也不受熔断保护——这会给东财带来一次不计
数的额外流量，这是本次实现新增的一个绕过点，与 `sources_cn.py` 顶部已记录
的 `stock_lhb_detail_em`/`stock_financial_analysis_indicator` 等同类限制一致。

**五年不足时的处理**：约 1220 个交易日为五年基准；某只股票上市不满五年、或
历史数据本身短于此，则按实际可得的交易日数计算分位数，并在买入区间的推导
式与看板中如实报告用了多少个交易日，绝不把「不足五年的分位数」包装成「五年
分位」呈现给用户。

**两处 `days_used` 口径不同，不要混用**：`sources_cn.fetch_pe_history` 返回
的 `days_used` 是「取数时截取的最近约 1220 个交易日总行数」，在过滤 PE 是否
为正之前统计；`compute.derive_valuation_anchor` 内部重新计算的 `days_used`
（写入 `val["meta"]["days_used"]`，最终体现在 `formula` 与 `prices.valuation`
里）是过滤掉非正值 PE（亏损期）之后的有效样本天数，两者只有在这段历史里从
未出现过 PE 为负/零时才会相等。看板与报告呈现的应该是后者（`meta` 里的
`days_used`），因为它才是真正参与分位数计算的样本量；两个数字都不是同一件
事，不能互相替代或混着引用。

**亏损（PE 为负或为零）时不构造估值锚**：当前 PE(TTM) ≤ 0 说明公司当期亏损
或数据异常，分位数排序对亏损公司没有意义（同样是负数，亏得多的和亏得少的谁
更「便宜」并无经济含义）。此时 `derive_valuation_anchor` 返回估值锚为空并
附带原因，`compute.py` 让买入区间退化为 `pricing.buy_range_technical_only`
——只用技术锚（MA20/前低/布林下轨）构造区间，并在推导式与备注里写明「估值
锚不可用」及具体原因，绝不能因为拿不到估值锚就沉默地展示一个看起来完整、实
则只有技术面支撑的区间。

**港股/美股当前没有五年 PE 历史数据源**：`yfinance` 只提供 `trailingPE`/
`forwardPE` 快照，没有历史序列接口，因此港股/美股当前无法实现 PE 五年分位。
`sources_hk_us.fetch_pe_history` 直接返回 `available=False` 并说明原因，
`compute.py` 据此省略估值锚、只用技术锚给买入区间，并在看板里明确写出「本
市场当前没有估值锚，仅技术面」。**绝不允许在港股/美股用「现价 ×
固定百分比」冒充估值锚**——那正是本次修复之前的缺陷本身：过去
`pricing.valuation_anchor(last * 0.85, last * 1.20)` 用当前收盘价的
85%~120%冒充估值区间，与 PE、与任何基本面数据都无关，只是把现价重新包了一
层「看起来像区间」的皮，在 600519 上曾出现估值锚 `[1083.89, 1530.19]` 与技
术锚 `[1168.63, 1298.32]` 取交集后恰好等于技术锚本身、估值锚对结果毫无贡献
的情况。这类近似已在 A 股上替换为真实的 PE 分位换算，港股/美股在数据源补齐
之前维持「省略并如实说明」，不能用同一套伪估值锚换个市场继续用。

## 快速看板为什么不跑完整 DCF

DCF（现金流折现）需要对未来自由现金流、永续增长率、折现率做多年展望和假
设，这类假设本身带有大量主观判断空间，而本 skill 定位是「个人快速决策看
板」，不是机构级深度研报，不适合在一次自动化流程里悄悄嵌入一套无法向用户
解释清楚假设依据的多年现金流预测。相对估值（PE/PB 分位）用的是历史已实现
的市场定价数据，可验证、可复现，更适合快速看板场景。如果用户需要更深入的
内在价值判断，应该在人工层面另行展开，而不是指望这个看板给出机构级 DCF
结论。
