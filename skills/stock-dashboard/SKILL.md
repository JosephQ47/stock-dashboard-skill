# 股票快速决策看板

个人用的快速决策看板：输入 1 到 3 只股票代码，落盘一份 Markdown 看板，包含
双轴评分（质量 Q / 时机 T）、财报排雷、技术面判断、带推导式的三个价位。这
是辅助个人决策的结构化输入，不替代用户自己的判断，也不是投资建议。

## 1. 先判断用户处在哪一步

| 用户说的话 | 对应模式 |
|---|---|
| "帮我看看 600519""这票怎么样""详细分析一下 AAPL" | 单只详细看板：走下方完整五步流程 |
| "这几只票哪个更好""对比一下 600519 和 000001""帮我选一只" | 多只对比（最多 3 只）：对每只都跑完整流程，额外在摘要中给出横向对比表 |
| "这票有没有雷""财报干净吗""查一下有没有暴雷风险" | 只排雷不估值：仍需运行 `fetch_data.py` 与 `compute.py` 取得真实数据，但只重点呈现第 4 节财报排雷，价位与技术面部分可简化为一句话带过 |

无法归入以上三类、或用户只是笼统问经济形势、基金组合、期货、加密货币时，
不使用本 skill。

## 2. 运行环境（先读，只读一次）

本 skill 的所有脚本必须使用项目专用虚拟环境的解释器：

```
D:\Economics\金融分析\.venv\Scripts\python.exe
```

**禁止使用裸命令 `python`**：本机系统 PATH 上排在最前的是 Anaconda base 的
解释器，其中没有本 skill 依赖的 akshare、baostock、yfinance 等库；曾经误把
依赖装进 base 导致其 numpy 版本被升级、致使 pandas 与 pyarrow 无法导入。绝
不允许再向 base 安装任何库。

下文所有「运行 `python scripts/xxx.py`」均指代用上述绝对路径调用，且工作目
录为本 skill 根目录（脚本内部按 `Path(__file__).parent` 定位自身，输出目录
由命令行参数传入，不依赖硬编码路径）。

## 3. 五步流程

**Step 0 前置自检**：确认今日日期，声明数据截止日；本次分析只使用脚本取回
的真实数据，不使用记忆中的财务数字。若是首次使用本 skill，或最近一次取数
失败，先运行 `python scripts/doctor.py` 检查解释器、依赖库、网络连通性与各
数据源可用性。

**Step 1 解析输入**：识别市场（A 股 / 港股 / 美股）与代码；若用户只给公司
名没给代码，联网搜索该公司名对应的股票代码，并与用户确认标的无歧义。

**Step 2 取数**：运行 `python scripts/fetch_data.py <代码...> --out <目录>`，
一次性拉取行情、三大报表、财务指标、技术面原始数据与市场特有项，产出
`<代码>_raw.json`。若提示网络不可用，多半是运行在禁网的沙箱环境中：告知用
户需要放开网络权限，或改用此前已生成的 JSON 继续后续步骤。

**Step 3 计算**：运行
`python scripts/compute.py --in <代码>_raw.json --out <代码>_computed.json`，
产出杜邦分解、红旗判定、估值分位、双轴分数、一票否决判定、三个价位及其推
导式。

**Step 4 分析**：按需读取 `references/scoring.md`（评分口径）、
`references/fundamentals.md`（排雷红旗定义）、`references/technicals.md`
（技术指标解读）、`references/market-cn.md` 或 `references/market-hk-us.md`
（对应市场特有项）；据此解读第 3 步的计算结果，识别两轴矛盾，列出多空理
由，标注硬数据与软数据。

**Step 5 输出**：运行 `python scripts/selfcheck.py --in <代码>_computed.json`
做出报前抽检；随后依 `references/output-template.md` 的模板结构，把报告写
入 `reports/{YYYY-MM-DD}-{代码}-看板.md`；聊天中只回一张摘要卡片与文件路
径，不在聊天里展开全文。

## 4. 硬规则清单

- 东财接口全局限速 2 秒间隔，单次看板对东财的总请求数上限 10 次；命中连接
  错误立即停止对东财的后续请求，本次运行内不再重试
- 巨潮接口必须用 POST 并带 `Content-Type: application/x-www-form-urlencoded`
- SEC 接口必须带含姓名与邮箱的 User-Agent
- 每条数据带 `source` 与 `fetched_at` 字段
- 硬数据（交易所披露：行情、财报、龙虎榜、两融）与软数据（主力资金流、筹
  码分布、千股千评）在看板中分区标注，软数据一律附口径警告
- 北向资金日频买卖明细自 2024-08-19 起官方已停止披露，看板中任何位置都不
  得出现该字段
- 数据完备率低于 70% 停止出结论，列出缺失项与人工核查链接（A 股给巨潮
  URL，美股给 EDGAR URL）
- 财务数据缺失不得推测填充，一律写「未获取到」
- 机械年化（如半年报乘 2）必须标注并降低数据置信度一档
- RSI14 超过 80 一律不给买入信号，只能给「等回调」
- 价格相对 MA5 乖离超过 5% 不给追高建议
- 两轴结论方向不一致时必须写出矛盾说明，不允许调和成模糊的「持有」「观
  望」
- frontmatter 与正文中不得出现任何宿主工具名；不得写死绝对路径（本环境说
  明中的解释器路径除外）

## 5. 错误处理表

| 情况 | 处理 |
|---|---|
| 依赖库缺失 | 提示用户执行 `pip install -r requirements.txt`（用上述 venv 解释器对应的 pip），不自动安装，不装入 Anaconda base |
| 单只股票取数失败 | 跳过该只并在看板中标注，不中断其他标的 |
| 接口限流 | 退避重试 3 次，每次间隔翻倍，仍失败则走降级链 |
| 休市或停牌 | 使用最近交易日数据并标注日期 |
| 数据完备率 < 70% | 停止出结论，输出缺失清单与人工核查链接 |
| 单只标的取数超过 120 秒 | 视为超时失败，按上面「单只股票取数失败」处理 |
| 网络不可用（常见于 Codex 沙箱） | `fetch_data.py` 启动时会先做连通性探测，失败即退出并提示；此时告知用户需要在当前环境中放开网络权限，或改用已缓存的 JSON 继续分析 |

## 6. 输出契约

- 落盘路径：`reports/{YYYY-MM-DD}-{代码}-看板.md`
- 同一天对同一代码重复生成时，不覆盖历史文件，文件名加 `-2`、`-3` 依次递
  增后缀
- 报告结构、每节内容与占位符规则见 `references/output-template.md`，必须逐
  节落实，不得省略章节
- 聊天回复只给一张摘要卡片（双轴分数、矩阵结论、一句话理由、三个价位）与
  文件路径，不在聊天里粘贴报告全文

## 7. 已知局限（据实说明，不得回避）

- 十个财报排雷红旗中，RECURRING（扣非占归母比）、AUDIT_OPINION（审计意
  见）、PLEDGE（股权质押）、DELISTING_RISK（退市风险）、INVESTIGATION（立
  案调查）这五项目前在任何市场都没有可用数据源，恒为「未获取到」。其中后
  四项具备一票否决权，意味着一票否决机制目前大部分时候处于休眠状态——只有
  实际取到数据的红旗才可能触发否决，「未获取到」不等于「已核查且清白」。
  实测中 600519 十条里能实际核查 3 条，AAPL 能核查 4 条
- 质量轴 Q 的五个维度中，护城河与估值水平这两项目前没有实现计算，分数只
  由财报排雷、盈利能力与成长、财务健康这三个维度构成，看板中须如实说明
- 估值锚（PE 五年分位）目前只对 A 股有效；港股与美股没有对应的历史 PE 数
  据源，第 8 节买入区间只能基于技术锚给出，不得用现价百分比冒充估值支持
- 北交所股票没有可用的财务报表数据源
- 北向资金日频明细数据自 2024-08-19 起已停止发布，看板任何位置都不得出现
- akshare 的内部网络调用会绕开本 skill 的限流器，因此东财请求上限只覆盖脚
  本直接发起的调用，不覆盖 akshare 内部产生的东财流量

参考实测：600519 质量分 96.74、时机分 37.73，结论「加入候选池，等技术面转
好」；AAPL 质量分 82.97、时机分 65.79，结论「重点关注，可建仓」。

## 8. 禁止交付的东西

- 不得在报告或摘要中出现「完成摘要」「TODO」「待补充」类占位文字
- 不得出现「此处应有图表/表格」一类的占位描述
- 不得出现未标注来源（`source` 与 `fetched_at`）的数字
- 不得用推测或记忆中的数字填补「未获取到」的字段
- 不得把两轴矛盾调和成「持有」「观望」等模糊结论
- 不得省略免责声明，也不得混淆「数据置信度」与「投资确定性」这两个独立维
  度
