## 一、Top 12 精读结果

### 1. anthropics/financial-services — `dcf-model`（官方核心）

- 来源：Anthropic 官方 "Claude for Financial Services"，https://github.com/anthropics/financial-services（旧名 `financial-services-plugins`）。34,804 stars，2026-09-12 仍在更新。
- 文件：https://github.com/anthropics/financial-services-plugins/blob/main/plugins/vertical-plugins/financial-analysis/skills/dcf-model/SKILL.md
- description：Real DCF model creation for equity valuation. Retrieves financial data from SEC filings and analyst reports, builds cash flow projections with proper WACC, performs sensitivity analysis, outputs professional Excel models.
- 结构：`SKILL.md`（约 50KB）+ `TROUBLESHOOTING.md` + `requirements.txt` + `scripts/validate_dcf.py`。依赖官方 `xlsx` skill 的 `recalc.py`。
- 流程（10 步）：数据获取与校验清单 → 3-5 年历史分析（CAGR、毛利/EBIT/FCF 边际、资本密集度、NWC、ROIC）→ 收入预测（近高远低、三情景）→ 费用建模 → FCF 构建（EBIT→NOPAT+D&A−CapEx−ΔNWC）→ WACC（CAPM，各类公司参考区间）→ 期中折现法 → 终值（永续增长 vs 退出倍数，TV 占 EV 50-70% 合理性检查）→ EV→Equity 桥 → 3 张 5×5 敏感性表。
- 数据源：MCP 优先（Daloopa、S&P Kensho、FactSet 等 11 家）→ 用户提供 → Web 搜索 → SEC EDGAR 兜底。
- 输出：`[Ticker]_DCF_Model_[Date].xlsx`，DCF + WACC 两个 sheet，Bear/Base/Bull 情景块 + case selector。
- 亮点：
  - "Formulas Over Hardcodes（非协商）"：所有推导值必须是活公式。
  - 每个硬编码单元格必须带 cell comment 注明来源（"Source: 10-K FY2024 Page 45 Note 12"），边写边加。
  - 分步与用户确认：数据→收入→FCF→WACC→终值→敏感性，不许端到端一次跑完。
  - 先锁定行布局再写公式；INDEX 合并列取代嵌套 IF；敏感性表奇数维、中心格=基准案例作为自检。
  - 显式 `<correct_patterns>` / `<common_mistakes>` 段，列出模型常见的合理化借口并要求拒绝。
- 弱点：单文件 50KB 上下文占用大；Excel 格式细节过多；强依赖付费 MCP；无内嵌计算脚本。

### 2. anthropics/financial-services — `comps-analysis`

- URL：https://github.com/anthropics/financial-services-plugins/blob/main/plugins/vertical-plugins/financial-analysis/skills/comps-analysis/SKILL.md
- description 附 "Perfect for / Not ideal for" 清单（不适用：无可比公众公司的私企、多元化集团、困境公司、pre-revenue）。
- 流程：数据源优先级（"NEVER use web search as primary source"）→ 先问四个问题（格式偏好、受众、核心问题、场景）→ 表头 → 经营指标区 → 估值倍数区 → 统计块（Max/75th/Median/25th/Min，只对比率做）→ Notes & Methodology。
- 框架："5-10 规则"（5 个经营指标+5 个估值指标）；按行业的必选/可选/跳过指标表；红旗清单（混用季度与 LTM、负 EBITDA 用 EBITDA 倍数、P/E>100x 无高增长故事）。
- 亮点："Better to have 3 perfect comps than 6 questionable ones"；Sanity check：GM > EBITDA margin > Net margin。

### 4. himself65/finance-skills — `company-valuation`

- 来源：https://github.com/himself65/finance-skills ，3,311 stars，2026-09-12 更新。
- 文件：https://github.com/himself65/finance-skills/blob/main/plugins/market-analysis/skills/company-valuation/SKILL.md
- description 极长、触发词密集（"what is AAPL worth", "fair value", "WACC"...），写明 "Default to running ALL three methods... Do not answer valuation questions from memory"。
- 结构：SKILL.md + `references/`（dcf.md、relative_valuation.md、sotp.md、wacc_erp_rates.md）。
- 流程（8 步）：环境检测（内联探测 yfinance、实时抓 `^TNX` 无风险利率）→ 方法适用性矩阵（成熟公司/SaaS/集团/银行/pre-revenue/REIT/周期股）→ 默认参数表（5 年、g=2.5%、ERP 5.5%、税率 3 年中位 floor 15%/cap 30%、同业 4-6 家取中位数、无 SOTP 时 DCF/相对各 50%）→ yfinance 拉数 → DCF（终值取 Gordon 与退出倍数中点）→ 相对估值 → SOTP → 三角化 + 5×5 敏感性 + Bull/Base/Bear → 固定 9 段输出。

- 弱点：yfinance 非官方易失效；缺少溯源要求。

## 二、共性模式总结

1. 三层结构成为标配：`SKILL.md`（触发 + 流程骨架 + 硬约束）→ `references/`（方法论、参数表、模板）→ `scripts/`（确定性计算、数据抓取）。
2. 数据源分层 + 降级链："优先 MCP → 用户提供 → 脚本/API → Web 搜索 → 默认值并注明"。
3. 反记忆、反幻觉条款："Do not answer from memory"；"训练数据已过期，先写下今日日期"；"禁止心算"；"不许用当前日期推断最新季度"。
4. 可追溯性是硬要求：cell comment、引用链接、来源编号 [n]、"Footnote every number"。
5. 默认参数表 + 门槛检查（Gates）：WACC ≤ g、TV/EV 超区间、隐含价格偏离 >2x 自动标红或中止。
6. 情景与敏感性是最低配置：Bear/Base/Bull + WACC×g 矩阵；中心格=基准案例；概率权重不许机械 25/50/25。
7. 强制"唱反调"：Self-Challenge、反向论证 ≥5 条失败路径、bear-case 红队、Invalidation Triggers。
8. 人机节拍：分步确认；或分步落盘、后步只读前步产物、聊天只给摘要。
9. 输出契约固定：固定文件名、章节顺序、"Headline verdict 一句话先行"、可点击引用、免责声明。
10. 反偷懒条款：列举模型常见借口并要求拒绝。

## 三、可借鉴设计清单

**结构层**：SKILL.md 控制在 5-10KB；description 塞满触发短语；方法论下沉 `references/`；抽出共享 `data-access.md` 与 `design-system.md`；写"何时不用"。

**数据层**：数据源降级链 + Web 白/黑名单；脚本抓数与算数，LLM 只填参数读结果；`endpoints.py` 集中接口；"完备率 <70% 停止"+ 错误处理表；开工先写今日日期、核对最新财报日期。

**分析层**：默认参数表（值+理由）+ 方法适用性矩阵；收入预测优先自下而上（行业 KPI 清单）；Gates；敏感性表奇数维中心=基准；"好公司 ≠ 好股票"质量与估值分离，一票否决前置；强制反向论证 + 可证伪信念 + Invalidation Triggers；概率权重必须解释。

**输出层**：每个数字带来源，全文【事实】【计算】【判断】【假设】【结论】标注；固定输出顺序（一句话结论 → 快照 → 方法汇总表 → 明细 → 敏感性 → 情景 → 3-5 条关键风险）；数据表后跟评论块；Excel 公式而非硬编码；报告落盘 `reports/{code}_{date}.md`，聊天只回摘要卡片；免责声明与数据截至日。

**流程控制层**：产物驱动的 Task 拆分 + 前置验证；关键节点（原始输入、收入预测、WACC）向用户确认；"禁止交付的东西"清单；可选 selfcheck 步骤。
