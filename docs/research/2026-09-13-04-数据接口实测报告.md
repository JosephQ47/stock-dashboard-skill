## 3. 限流复现实验（关键发现）

对失败项间隔 3 秒重试两轮，并用裸 HTTP 打同样的东财接口对照：

| 方式 | 接口 | 结果 |
|---|---|---|
| akshare | A股历史K线（东财） | 两轮均失败 |
| akshare | 港股历史K线（东财） | 两轮均失败 |
| 裸 HTTP | 东财 push2his A股K线 | **失败**（首轮曾成功） |
| 裸 HTTP | 东财 push2his 港股K线 | **失败** |
| 裸 HTTP | 腾讯 A股行情 | 可用，1275.16 |
| 裸 HTTP | 腾讯 港股行情 | 可用，428.400 |

**结论**：东财在本次测试过程中按源 IP 实施了限流。同一接口首轮可用、多次请求后整体不可达，且 akshare 封装与裸 HTTP 表现一致，说明这不是库的问题而是服务端封禁。腾讯接口在同一时段始终稳定。

## 4. 对设计的影响

### 4.1 东财不能作为关键路径首选

原 spec 把东财 datacenter 列为龙虎榜、两融、解禁的首选，把东财列为行情降级源。实测表明东财会整体性失效，且失效期间所有东财接口一起不可用，降级链里放两个东财源等于没有降级。

修正后的优先级：

| 数据类 | 首选 | 降级 1 | 降级 2 |
|---|---|---|---|
| A股 实时行情 | 腾讯 qt.gtimg.cn | 新浪 | 东财 push2 |
| A股 历史K线 | baostock | 腾讯 | 东财 push2his |
| A股 三大报表 | akshare 新浪源 `stock_financial_report_sina` | akshare 同花顺源 | 巨潮公告人工核查 |
| A股 财务指标 | akshare `stock_financial_analysis_indicator` | 由三表自算 | — |
| A股 业绩预告 | akshare `stock_yjyg_em` | 巨潮公告 | — |
| A股 龙虎榜/两融/解禁 | akshare 东财源 | 交易所官网 | 标注未获取到 |
| 港股 行情 | 腾讯 hk | yfinance | akshare 港股 |
| 美股 行情与财务 | yfinance | SEC EDGAR | — |
| 美股 权威财务 | SEC companyconcept / submissions | — | — |
| 公告全文 | 巨潮（POST） | 交易所官网 | — |

### 4.2 东财类数据降级为「尽力而为」

龙虎榜、两融、解禁这些只有东财有的数据，取不到时直接标注「未获取到」并给出交易所人工核查链接，不阻断整个看板流程。这些本来就属于软数据或辅助项，缺失不影响双轴评分的主干。

### 4.3 限速必须比社区建议更保守

社区建议东财间隔 1 秒。本次测试在间隔 1 到 3 秒的情况下仍被封，说明真实阈值与累计请求量有关，不只与间隔有关。设计上：

- 东财接口全局限速 2 秒间隔，单次看板对东财的总请求数上限 10 次
- 命中 ConnectionError 或 RemoteDisconnected 立即停止对东财的后续请求，本次运行内不再重试
- 优先用腾讯与 baostock 覆盖行情与 K 线，把东财的配额留给它独有的数据

### 4.4 巨潮必须用 POST

`topSearch/query` 与 `hisAnnouncement/query` 都是 POST，且需要 `Content-Type: application/x-www-form-urlencoded`。GET 会返回 HTTP 500。

### 4.5 SEC 必须带真实 User-Agent

SEC 要求 User-Agent 包含姓名与邮箱，否则拒绝。已验证 `"Robin Quan robin.quan@potentia.ai"` 可用。

## 5. 环境隔离结论

### 5.1 不要装进 Anaconda base

本次测试初期误将 akshare 等装入 `D:\anaconda3` 的 base 环境，`pip` 为满足依赖把 numpy 从 2.x 升到 2.2.6，导致该环境中用 numpy 1.x 编译的 pandas 2.2.2 与 pyarrow 14.0.2 全部无法导入。

已完成修复：卸载三个金融库，numpy 固定回 1.26.4。base 环境验证结果：

| 包 | 状态 |
|---|---|
| numpy | 1.26.4 |
| pandas | 2.2.2，冒烟测试通过 |
| pyarrow | 14.0.2 |
| cv2 | 4.12.0 |
| streamlit | 1.32.0 |
| matplotlib | 3.8.4 |
| scipy | 1.13.1 |
| sklearn | 1.8.0 |
| torch | 仍报 OSError |

torch 的 c10.dll 加载失败在 numpy 1.26.4 与 2.2.6 下表现完全相同，属于 DLL 依赖问题，与本次操作无关，是先前就存在的状态。

## 6. 对「其他 agent 能否取到数据」的回答

不能无条件保证。可靠性分三档：

**高可靠**：腾讯行情、baostock、yfinance、SEC EDGAR、巨潮 POST、akshare 的新浪源财务接口。本次全部稳定。

**中可靠**：akshare 的业绩预告与龙虎榜。依赖东财，本次可用但同属高风险源。

**低可靠**：东财全部行情接口。本次测试中被限流后整体不可达，且恢复时间未知。

因此 skill 必须自带一个环境自检脚本，运行前逐项探测并报告哪些源当前可用，而不是假设它们都在。这一条要写进实现计划。
