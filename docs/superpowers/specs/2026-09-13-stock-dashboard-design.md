## 1. 目标与定位

一个个人用的快速决策看板 skill。输入 1 到 3 只股票代码，输出一份落盘的 Markdown 看板：双轴评分、关键指标、财报排雷、技术面判断、带推导过程的三个价位、矛盾点与风险提示。

**不做什么**：不做 30 页深度研报，不做多 Agent 编排，不做回测与自动交易，不做 Excel 公式级建模，不做机构付费数据源接入。

**用户画像**：个人投资者，中文输出，自己做最终决策，需要的是快速形成判断的结构化输入，而不是被 AI 替代判断。

## 3. 目录结构

源码唯一副本放在项目内，两端通过目录联接指向它：

```
D:\Economics\金融分析\skills\stock-dashboard\      ← 唯一源
  ↑ 目录联接                    ↑ 目录联接
~/.claude/skills/stock-dashboard   ~/.codex/skills/stock-dashboard
```

Windows 上用 `New-Item -ItemType Junction` 创建，不需要管理员权限（已验证）。改一处两端同时生效，不存在副本漂移。

```
skills/stock-dashboard/
├── SKILL.md                  # 触发条件 + 5 步流程 + 硬规则 + 错误处理，目标 6-8KB
├── references/
│   ├── data-sources.md       # 三市场数据源、降级链、限速、硬软数据分级
│   ├── scoring.md            # 双轴评分卡：每个维度的指标、阈值、给分规则
│   ├── fundamentals.md       # 财报排雷红旗表、勾稽校验、估值分位口径
│   ├── technicals.md         # 8 个互补指标的定义与解读规则
│   ├── market-cn.md          # A 股特有项：龙虎榜、两融、解禁、减持新规、ST 红线
│   ├── market-hk-us.md       # 港股美股差异：SEC 口径、A/H 折溢价、财报节奏
│   └── output-template.md    # 看板模板：汇总表 + 个股卡片
├── scripts/
│   ├── endpoints.py          # 接口 URL、限速常量、venv 解释器路径
│   ├── doctor.py             # 环境与数据源自检，逐项探测可用性
│   ├── fetch_data.py         # 统一取数入口：市场识别 → 降级链 → JSON
│   ├── compute.py            # Decimal 精确计算：指标、分位、勾稽、评分
│   └── selfcheck.py          # 出报告前抽检数字与数据完备率
├── requirements.txt          # 锁定版本，供其他机器复现环境
└── install.ps1               # 在两端创建目录联接，可重复执行
```

**边界约定**：
- `SKILL.md` 只写流程骨架与硬规则，方法论一律下沉到 `references/`，按步骤按需加载
- `fetch_data.py` 是唯一取数入口，对话层不需要知道内部用了哪个数据源
- `compute.py` 不联网，只吃 `fetch_data.py` 的 JSON，纯函数便于单测
- 脚本之间通过 JSON 文件通信，不通过内存对象，便于中断续跑与人工检查

## 3.5 双端兼容规则

Claude Code 与 Codex 的 skill 格式一致：frontmatter 只含 `name` 与 `description`，正文 Markdown，同样支持 `references/` 与 `scripts/` 子目录。差异集中在三处，按以下规则消除。

### 3.5.1 frontmatter 保持最小

只写 `name` 与 `description` 两个字段。不使用 `allowed-tools`、`license`、`argument-hint` 等任一端特有字段，避免另一端解析异常或行为不一致。

### 3.5.2 正文不得出现宿主工具名

SKILL.md 与所有 `references/` 文件中，动作一律写成工具中性的描述。

| 禁止写法 | 应写成 |
|---|---|
| 用 Read 工具读取 `references/scoring.md` | 读取 `references/scoring.md` |
| 用 Bash 运行脚本 | 运行 `python scripts/fetch_data.py` |
| 用 WebSearch 查代码 | 联网搜索公司名对应的股票代码 |
| 用 Write 工具写报告 | 将报告写入 `reports/...` |

理由：Claude Code 的工具名是 Read、Write、Edit、Bash、WebSearch；Codex 走 shell 与 apply_patch。写死任一端的工具名会让另一端的模型困惑或照搬不存在的工具。

### 3.5.3 脚本调用方式统一

- 一律 `python scripts/xxx.py`，不依赖 shebang，不用 `./xxx.py`
- 路径一律相对 skill 根目录，不写绝对路径
- 脚本内部不假设工作目录，用 `Path(__file__).parent` 定位自身
- 输出目录由命令行参数传入，不硬编码

### 3.5.4 网络可用性前置检测

Codex 在沙箱模式下可能禁止网络访问，取数会静默失败或超时。`fetch_data.py` 启动时先做一次轻量连通性探测，失败则立即退出并打印明确提示，而不是逐个接口重试到超时。

SKILL.md 中写明：若提示网络不可用，告知用户需要在 Codex 中放开网络权限，或改用已缓存的 JSON 继续分析。

### 3.5.5 安装方式

`install.ps1` 负责在两端创建目录联接，脚本可重复执行：已存在的联接先移除再重建，遇到真实目录（而非联接）则报错退出，避免误删用户数据。

## 4. 数据层

### 4.1 市场识别

| 代码形态 | 市场 | 示例 |
|---|---|---|
| 6 位数字，6 开头 | 上交所 | 600519 |
| 6 位数字，0 或 3 开头 | 深交所 | 000001、300750 |
| 6 位数字，8 或 4 开头 | 北交所 | 830799 |
| 5 位数字或 HK 前缀 | 港股 | 00700、HK00700 |
| 纯字母 | 美股 | AAPL |

公司名转代码用 WebSearch，禁止拉全市场行情表来做匹配。

### 4.2 数据源与降级链

以下优先级来自 2026-09-13 的实测，不是纸面假设。完整测试记录见 `docs/research/2026-09-13-04-数据接口实测报告.md`。

核心实测结论：东财接口会按源 IP 整体限流，本次测试中首轮可用、多次请求后全部不可达，且 akshare 封装与裸 HTTP 表现一致。因此东财不得作为任何关键路径的首选，降级链中也不得出现两个东财源。

| 数据类 | 首选 | 降级 1 | 降级 2 |
|---|---|---|---|
| A股 实时行情 | 腾讯 qt.gtimg.cn | 新浪 | 东财 push2 |
| A股 历史 K 线 | baostock | 腾讯 | 东财 push2his |
| A股 三大报表 | akshare 新浪源 `stock_financial_report_sina` | akshare 同花顺源 | 巨潮公告人工核查 |
| A股 财务指标 | akshare `stock_financial_analysis_indicator` | 由三表自算 | — |
| A股 业绩预告 | akshare `stock_yjyg_em` | 巨潮公告 | — |
| A股 龙虎榜、两融、解禁 | akshare 东财源 | 交易所官网 | 标注未获取到 |
| 港股 行情 | 腾讯 hk | yfinance | akshare 港股 |
| 美股 行情与财务 | yfinance | SEC EDGAR | — |
| 美股 权威财务 | SEC companyconcept / submissions | — | — |
| 公告全文 | 巨潮（POST） | 交易所官网 | — |

**实测可靠性分档**：

- 高可靠：腾讯行情、baostock、yfinance、SEC EDGAR、巨潮 POST、akshare 新浪源财务
- 中可靠：akshare 业绩预告与龙虎榜，依赖东财
- 低可靠：东财全部行情接口

龙虎榜、两融、解禁属于东财独有数据，取不到时直接标注「未获取到」并给出交易所核查链接，不阻断看板主流程。这些是软数据或辅助项，缺失不影响双轴评分主干。

### 4.3 硬规则

- 东财接口全局限速 2 秒间隔，单次看板对东财的总请求数上限 10 次
- 命中 ConnectionError 或 RemoteDisconnected 立即停止对东财的后续请求，本次运行内不再重试
- 巨潮接口必须用 POST 并带 `Content-Type: application/x-www-form-urlencoded`，GET 会返回 HTTP 500
- SEC 接口必须带含姓名与邮箱的 User-Agent，否则被拒
- 每条数据带 `source` 与 `fetched_at` 字段
- 硬数据（交易所披露：行情、财报、龙虎榜、两融）与软数据（主力资金流、筹码分布、千股千评）在看板中分区标注，软数据一律附口径警告
- 北向资金日频买卖明细自 2024-08-19 起官方已停止披露，看板中不得出现该字段
- 数据完备率低于 70% 停止出结论，列出缺失项与人工核查链接（A 股给巨潮 URL，美股给 EDGAR URL）
- 财务数据缺失不得推测填充，写「未获取到」
- 机械年化（如半年报乘 2）必须标注并降低数据置信度一档

## 5. 评分层

### 5.1 质量轴 Q（0-100），回答「值不值得拿」

| 维度 | 权重 | 主要指标 |
|---|---|---|
| 财报质量与排雷 | 30 | 净现比、应计比率、应收与营收增速差、商誉占净资产、扣非占归母比 |
| 盈利能力与成长 | 25 | ROE、ROIC、毛利率趋势、营收与扣非净利增速 |
| 财务健康 | 15 | 资产负债率、流动比率、有息负债、利息保障倍数 |
| 护城河与竞争地位 | 15 | ROIC 持续性、毛利率稳定度、资本开支强度 |
| 估值水平 | 15 | PE/PB 五年分位、PEG、EV/EBITDA 对同业 |

### 5.2 时机轴 T（0-100），回答「现在是不是时候」

| 维度 | 权重 | 主要指标 |
|---|---|---|
| 趋势 | 30 | 价格相对 MA20/MA60/MA120、均线排列 |
| 动量 | 25 | RSI14、MACD、1/3/6 月相对收益 |
| 量能与资金 | 20 | 量比、换手率、主力净流入（软）、两融余额变化 |
| 位置 | 15 | 距前高前低幅度、布林带位置、ATR 相对波动 |
| 催化与情绪 | 10 | 财报日历、解禁减持、新闻情绪 |

技术指标固定取 8 个互补指标，不得堆砌：MA20、MA60、MA120、RSI14、MACD、布林带、ATR14、成交量均线。

### 5.3 矩阵映射

Q 与 T 各以 60 为界：

| | T ≥ 60 | T < 60 |
|---|---|---|
| Q ≥ 60 | 重点关注，可建仓 | 加入候选池，等技术面转好 |
| Q < 60 | Q ≥ 45 标为「短线博弈」并注明不是投资；Q < 45 标为回避 | 回避 |

**矛盾显式化**：两轴结论方向不一致时，看板必须写出一句矛盾说明，例如「基本面扎实但价格在下降趋势中，等待站回 MA60 再谈」。不允许调和成模糊的「持有」。

### 5.4 一票否决

命中任意一条：非标审计意见、立案调查、退市风险、净现比连续两年低于 0.5、大存大贷、股权质押超 50%。

后果：Q 轴封顶 40 分，结论强制为回避，看板顶部红字标出触发原因与证据来源。

## 6. 价位推导

三个价位都必须写出推导式与输入值，不允许直接报数字。

| 价位 | 推导方式 |
|---|---|
| 买入区间 | 估值锚与技术锚取交集；交集为空时说明原因并给更靠近的一侧。估值锚用相对估值：PE 五年分位的 25 分位对应价格为下沿。快速看板不跑完整 DCF |
| 目标价 | 估值区间上沿与前高阻力位取较低者，标注对应的隐含 PE |
| 止损价 | ATR 法（入场价减 2 倍 ATR14）与结构法（前低下方 1%）取更近者 |

**价位相关硬规则**：
- RSI14 超过 80 一律不给买入信号，只能给「等回调」
- 价格相对 MA5 乖离超过 5% 不给追高建议
- 涨停、跌停、停牌、ST 状态下的特殊处理写入 `references/technicals.md`

## 7. 工作流

**Step 0 前置自检**：写下今日日期；声明数据截止日；禁止使用模型记忆中的财务数据。

**Step 1 解析输入**：识别市场与代码；公司名走 WebSearch 转代码；确认标的无歧义。

**Step 2 取数**：调用 `fetch_data.py`，一次性拉全量（行情、三表、指标、技术数据、市场特有项），输出 JSON 到工作目录，附 `data_sources` 状态块。

**Step 3 计算**：调用 `compute.py`，产出指标、分位、勾稽校验结果、双轴分数、一票否决判定、三个价位及推导式，输出 JSON。

**Step 4 分析**：读 `references/` 中对应的方法论文件，对计算结果做解读；识别两轴矛盾；列出多空理由与红旗；标注硬软数据。

**Step 5 输出**：按 `output-template.md` 写入 `reports/{日期}-{代码}-看板.md`；调用 `selfcheck.py` 抽检；聊天中只回摘要卡片与文件路径。

## 8. 输出契约

**落盘文件**：`reports/{YYYY-MM-DD}-{代码}-看板.md`，同日重跑加 `-2` 后缀，不覆盖历史。

**文件结构**：
1. 顶部结论框：标的、双轴分数、矩阵结论、一句话理由、数据截止日
2. 一票否决红字警示（如触发）
3. 关键指标速览表（硬数据区）
4. 财报质量与排雷（红旗逐条列出，命中标 ❗，未命中标 ✓）
5. 估值分位
6. 技术面（8 指标表 + 解读）
7. 市场特有项（A 股：龙虎榜、两融、解禁；美股：内部人交易）—— 软数据区，带口径警告
8. 三个价位与推导式
9. 两轴矛盾说明（如存在）
10. 多空理由各 3 条
11. 数据来源清单与缺失项
12. 免责声明，并区分「数据置信度」与「投资确定性」

**聊天回复**：只回一张摘要卡片（双轴分数、结论、一句话理由、三个价位）与文件路径。

## 9. 错误处理

| 情况 | 处理 |
|---|---|
| 依赖库缺失 | 提示用户执行 pip 安装命令，不自动安装 |
| 单只股票取数失败 | 跳过该只并在看板中标注，不中断其他标的 |
| 接口限流 | 退避重试 3 次，每次间隔翻倍，仍失败则走降级链 |
| 休市或停牌 | 使用最近交易日数据并标注日期 |
| 数据完备率 < 70% | 停止出结论，输出缺失清单与人工核查链接 |
| 脚本超时 | 单只标的取数上限 120 秒 |
| 网络不可用（Codex 沙箱） | 启动时探测即失败，提示放开网络权限或改用已缓存 JSON |

## 10. 运行环境

**必须使用项目专用虚拟环境，禁止装入 Anaconda base。**

```
D:\Economics\金融分析\.venv\Scripts\python.exe
```

已创建并验证，内含 akshare 1.18.94、baostock 0.9.3、yfinance 1.7.0、numpy 2.5.3、pandas 3.0.5。

**原因**：安装 akshare 会把 numpy 升级到 2.x，而 Anaconda base 中的 pandas 2.2.2 与 pyarrow 14.0.2 是用 numpy 1.x 编译的，升级会导致这些包全部无法导入。本次设计阶段曾误装入 base 并造成该故障，已通过卸载并固定 numpy 1.26.4 修复。

**脚本调用约定**：所有脚本必须显式使用 venv 解释器的绝对路径，不能写 `python`，因为系统 PATH 上第一个是 Anaconda base 的解释器。SKILL.md 中将该路径定义为唯一入口常量，便于换机时只改一处。

**跨机器可移植**：随 skill 提供 `requirements.txt` 锁定版本，以及 `python -m venv` 的建环境步骤，让其他机器或其他 agent 能复现同一环境。

### 10.1 环境自检

新增 `scripts/doctor.py`，在正式取数前逐项探测数据源可用性并输出报告，包括：

- venv 解释器是否正确、三个库能否导入
- 网络连通性（Codex 沙箱可能禁网）
- 各数据源逐个探测：腾讯、baostock、akshare 新浪源、yfinance、SEC、巨潮、东财
- 输出每个源的可用与否，标出当前可走的降级路径

理由：实测证明数据源可用性会随时间与 IP 状态变化，不能假设它们都在。SKILL.md 规定首次使用或取数失败时先运行 doctor。
